2.2 — Key Definitions & Master Concepts

  • PERT (Program Evaluation & Review Technique): Event-oriented, probabilistic project management technique using three time estimates (to,tm,tpt_o, t_m, t_pto​,tm​,tp​). Ideal for R&D and non-repetitive projects (e.g., Polaris missile development).
  • CPM (Critical Path Method): Activity-oriented, deterministic project management technique using single time estimates. Ideal for construction, maintenance, and civil engineering projects.
  • Event / Node: Point in time representing the start or completion of one or more activities. Consumes zero time and zero resources.
  • Activity: Element of work required to complete a project. Consumes time and resources.
  • Dummy Activity: Imaginary activity represented by a dashed arrow (⇢\dashrightarrow⇢). Consumes zero time and zero resources. Used solely to preserve logical precedence and prevent two activities from sharing identical head/tail nodes.
  • Fulkerson’s Rule: Systematic algorithm for numbering network nodes from left to right (initial node 111; re-number remaining nodes sequentially such that for every activity i→ji \to ji→j, i<ji < ji<j).
  • Critical Path: Longest continuous path through the network diagram. Dictates the minimum project completion time. Activities on the critical path have zero total float (TF=0TF = 0TF=0).
  • Slack (Event Slack): S=L−ES = L - ES=L−E. Difference between Latest Allowable Occurrence time (LLL) and Earliest Expected Occurrence time (EEE) of an event. (Positive = ahead; Zero = critical; Negative = behind schedule).
  • Total Float (TFTFTF): Maximum delay an activity can experience without delaying the overall project completion date (TF=LS−ES=LF−EFTF = LS - ES = LF - EFTF=LS−ES=LF−EF).
  • Free Float (FFFFFF): Delay an activity can experience without delaying the Earliest Start (ESESES) of any immediate successor activity (FF=ESnext−EFcurrentFF = ES_{\text{next}} - EF_{\text{current}}FF=ESnext​−EFcurrent​).
  • Independent Float (IFIFIF): Portion of float that can be used without affecting either preceding or succeeding activities (IF=ESnext−LFprev−tIF = ES_{\text{next}} - LF_{\text{prev}} - tIF=ESnext​−LFprev​−t).
  • Crashing: Process of reducing overall project duration by allocating additional resources to critical path activities at the lowest incremental cost slope.
  • Optimum Project Duration: Duration that minimizes Total Project Cost (where Direct Cost curve meets Indirect Cost curve).

SECTION 3: MAIN BODY

3.1 — PERT vs CPM Fundamentals & Network Rules

1. Concept Pointers
  • PERT Characteristics:
    • Event-oriented; probabilistic model using Beta distribution for activity durations and Normal distribution for overall project completion.
    • Developed for non-repetitive, uncertain R&D projects (Polaris missile).
  • CPM Characteristics:
    • Activity-oriented; deterministic model assuming known durations.
    • Developed for repetitive construction, plant overhaul, and industrial maintenance projects.
  • Dummy Activities:
    • Represented by dashed arrows (⇢\dashrightarrow⇢).
    • Consume zero time and zero resources.
    • Used strictly for two reasons: (1) Maintain logical precedence, (2) Avoid two activities sharing identical start (iii) and end (jjj) nodes.
    • Examiner Trap: Dummy activities NEVER consume resources or time, and cannot lie on a critical path if an alternative real path exists with positive duration.
  • Fulkerson’s Rule for Node Numbering:
    1. Initial event (no incoming arrows) is numbered 1.
    2. Delete all outgoing arrows from node 1; identify new initial nodes.
    3. Number new initial nodes sequentially (2,3,…2, 3, \dots2,3,…).
    4. Repeat until final terminal event is numbered.
    5. Rule enforces: For every activity i→ji \to ji→j, i<ji < ji<j.

1. Concept Pointers
  • Three Time Estimates:
    1. Optimistic Time (tot_oto​): Minimum possible time if everything goes exceptionally well.
    2. Most Likely Time (tmt_mtm​): Modal duration required under normal operating conditions.
    3. Pessimistic Time (tpt_ptp​): Maximum possible time if adverse conditions occur (excluding natural disasters).
  • Expected Time (tet_ete​):

3.5 — CPM Project Crashing & Time–Cost Trade-off

1. Concept Pointers
  • Crashing Objective: Reduce total project duration to meet a target deadline or minimize Total Project Cost.
  • Cost Slope: Extra direct cost incurred per unit time reduction:
    Cost Slope=Cc−CnTn−Tc\text{Cost Slope} = \frac{C_c - C_n}{T_n - T_c}Cost Slope=Tn​−Tc​Cc​−Cn​​
  • Total Project Cost:
    Total Cost=Direct Costs+Indirect Costs\text{Total Cost} = \text{Direct Costs} + \text{Indirect Costs}Total Cost=Direct Costs+Indirect Costs
    • As project duration decreases: Direct Costs INCREASE, Indirect Costs DECREASE.
  • Crashing Rules:
    1. Crash ONLY critical path activities. Crashing a non-critical activity wastes money without shortening project length.
    2. Among critical activities, crash the one with the LOWEST cost slope first.
    3. Crash until the activity reaches its crash limit (TcT_cTc​) or a new parallel critical path emerges.
    4. When multiple critical paths exist, crash activities simultaneously across ALL critical paths such that the sum of cost slopes is minimized.
    5. Stop crashing when the cost slope exceeds the daily indirect cost savings (Optimum Point).

SECTION 4: CONSOLIDATION NOTES

Note on Slack vs Float

  • Slack is an event property (S=L−ES = L - ES=L−E), primarily used in PERT.
  • Float is an activity property (TF,FF,IFTF, FF, IFTF,FF,IF), primarily used in CPM.
